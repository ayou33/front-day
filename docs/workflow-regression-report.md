# 前端的一天全流程回归与改进报告

本次回归覆盖从登记本地项目、维护项目和迭代背景，到执行任务、续改、归档和切换数据目录。新增的厂商 API 与本地 Agent 共用执行器选择。厂商密钥集中在「引擎与 API」，提示词优化在「配置」启用。

## 回归覆盖

上次回归通过 37 项用例，包括 2 项浏览器流程和 11 项厂商协议子用例。

| 流程 | 核对内容 | 验证方式 |
| --- | --- | --- |
| 项目与迭代 | 浏览目录、按目录推导项目名、编辑项目背景、创建迭代、继承项目与迭代要素及迁移旧版迭代信息 | 浏览器、接口 |
| 要素与 HTTP 账户 | 文本、URL、本机文件与文件夹、自定义类型、加密保存账户密码、同源绑定和读取失败提示 | 浏览器、接口、回环资料服务 |
| 本地引擎 | 发现本机 CLI、缺失引擎折叠、手动检查、认证状态、Cursor Auto、Codex 配置目录在重启后复用 | 浏览器、模拟 CLI |
| 厂商 API | 预设与自定义模型、切换厂商保留配置、旧版优化配置兼容、密钥移除、重启及迁移后读取凭据 | 浏览器、接口、11 家厂商请求与响应样例 |
| 提示词优化 | 关停后拒绝调用、切换本地引擎和厂商 API、优化任务目标和已保存任务的提示词、确认后应用 | 浏览器、模拟 CLI 和 API |
| 任务与上下文 | 直接开始、保存后编辑及启动、项目必选、任务类型与补充信息、发送前预览以及启动后的编辑限制 | 浏览器、接口 |

## 验证范围

`pnpm build` 通过。`pnpm exec node --test tests/*.test.ts tests/browser.spec.ts` 全部通过，共 42 项，含 2 项浏览器流程。浏览器核对了手动 API 检查、启动时自动使用最新资料、查看审批差异、批准写入和验收结果。

新增回归覆盖同厂商多配置与连接诊断、服务端资料范围、启动时自动使用最新资料、分段读写与重复授权、真实子进程验收、续改链分页。厂商联通结果和 token 用量使用模拟响应核对。厂商未返回用量时界面标明缺失，预算按已上报用量判断。真实账号与不同模型的流式兼容性仍待现场核对。

资料范围控制适用于工作台自动组装的资料及 API 工具。用户手动填写或编辑的提示词正文按原文发送。文件验收核对实际改动，功能表现由项目测试或人工验收确认。原生 CLI 工作区扫描受文件数量、总大小及目录深度限制，超出时显示未自动验收。

厂商 API 的续改通常沿用交接摘要并归入源任务。有排除要素时略去自动交接摘要及上一阶段正文，测试只传退出码。原生 CLI 续接取决于已有会话、工作目录、模型和兼容性。
